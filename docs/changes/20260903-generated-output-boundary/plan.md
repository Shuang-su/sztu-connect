# 实施计划

## 目标与边界

只修复已复现的生成输出目录越界问题，保持用户已修改的内容扫描、记录校验、知识导出规则和 README 原文不变；完成本地提交、分支推送、远端检查和合并。

## 提交安排

1. 核对分支、工作区、远端 `main`、现有 PR 和发布权限，复跑用户现有的 51 项测试。
2. 将用户手动修改的六个文件原样保存为独立 checkpoint，便于审查其与 Agent 修复的区别。
3. 增加能在修复前失败的回归测试，再修复 `src/sztu_connect/build.py`；请求与计划记录随修复提交。
4. 完成所有本地验收后，单独提交完成记录，记录前序 checkpoint SHA，避免在同一提交中引用自身 SHA。

## 输出边界修复

- 在任何构建文件写入前，统一检查 `data`、`data/generated`、`data/generated/directories`、`data/generated/knowledge`。
- 检测到符号链接时，返回结构化失败结果；包括目标尚不存在的悬空链接。
- 失败前不创建部分时间线、目录或知识输出，不改动链接，不覆盖仓库外已有的同名文件。
- 保持普通目录和首次构建可用，不恢复全仓库符号链接禁令；正式记录的符号链接准入和隐私扫描行为保持用户版本。

## 回归与验收

- 为两个生成子目录增加外部链接测试，使用临时仓库和测试标记文件验证“失败、无部分输出、外部同名文件不变”。
- 为四级输出路径增加悬空链接测试，验证不会写入或泄漏底层文件系统异常。
- 先记录修复前测试失败，再确认同一组测试在修复后通过。
- 运行配置 JSON 解析、`doctor`、`validate`、普通及严格隐私扫描、两次构建、普通及严格 `check`、完整单元测试、编译检查与 `git diff --check`。
- 比较已跟踪生成文件的 SHA-256，确认两次构建以及修复前后的现有派生数据一致。
- 核对用户的 README 和未涉及修复的四个文件仍为开始本轮时的 Git blob，正式 Event、Node、Collection、Source 数量没有变化。
- 推送前独立审阅待发布的文件与提交，不以放宽后的扫描退出码替代内容审阅。

## 发布

- 普通推送 `codex/readme-archive-onboarding`，不强推、不删除分支、不改写历史。
- 使用现有 PR；若没有，则创建以 `main` 为目标的 PR，以触发仓库现有检查。
- 等待 PR 检查通过，核对实际 head SHA 与合并状态，再以 merge commit 合并，保留各个独立提交。
- 不绕过保护规则、失败检查或所需审批。若出现新的无关问题，报告实际阻塞，不擅自扩大修复范围。
- 合并后回读 PR、远端 `main` 与对应 CI，确认发布结果；最终回复给出 PR、提交和检查结果。
