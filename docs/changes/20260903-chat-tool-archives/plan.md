# 最终实施计划

日期：2026-09-03。状态：经用户确认，实施与验收结果见 [completion.md](completion.md)。

## 目标与范围

为 SZTU Connect 提供可核对来源的现成聊天工具目录：实际保存两个固定源码快照，给使用者稳定的上游安装包入口，更新现有技能，使用户可以把原始聊天导出作为 Source 引用。研究说明各项目的支持版本、存档链和替代价值。

选型依据优先来自原作者仓库、固定提交、可比较 forks、Release/API、构建日志、原始许可证和作者回复。区分源码证据、项目方声明、本地文件检查与运行实测；未知项不填成已验证。

## 1. 两份实体源码存档

在根目录 `importers/` 下按平台、项目、版本保存完整未修改的源码归档：

- CipherTalk-SafeFork：`2026.829.0`，提交 `acf221c11ecb1afae32e88885b2309dd39f0f161`。
- WeChatMsg：`3.0.0` 的原作者历史快照，提交 `9457ecdad74826ebede9a040b1d86d986c968f1e`。

通过完整提交的 GitHub codeload 下载；保留原文件名、原始归档字节和独立许可副本。登记来源 URL、提交、tree、下载时间、实际大小和 SHA-256。源码快照包含上游预编译文件，不声称所有内容均有可复现源码。

第三方归档里的 AGENTS、skills、工作流、安装脚本只作为数据保存，不注册、不安装、不执行，也不让它们覆盖本仓库配置。

## 2. 上游安装包入口，不使用 Git LFS

- CipherTalk DMG 和 EXE 固定到 `v2026.829.0` Release；不使用 latest，不进行安装包镜像发布。
- 记录资产 ID、大小、平台架构及上游 API 摘要，明确没有本地安装包下载和运行验证。
- 保留用户下载后自行计算 SHA-256 的命令。上游链接或摘要变化时先核查，不自动换陌生镜像。
- 不把源码归档称为现成安装包；WeChatMsg 暂无已核实的同提交持久 EXE，只标记源码备用。

## 3. 更新现有技能与文档

- `map-chat-to-events`：没有导出时按系统/架构/微信版本选择目录入口；已有原件时直接清点和引用；只有用户需要时才映射 JSONL、生成 HTML 或候选事件。
- `record-campus-event`：原始聊天导出可直接作为 Source，保留实际文件摘要和精确消息定位；不以工具 Release URL 代替聊天来源。
- `fact-check-event`：分别检查工具来源、原件字节连续性和发言的事实性；区分服务器 ID、本地 ID、导出序号，不把复制/重导出计为独立来源。
- 共享细节集中在 `docs/CHAT_IMPORT.md` 与 `importers/README.md`，不在多个技能中复制不断变化的版本矩阵。
- README 只调整相关入口、目录和致谢/许可描述；根 `LICENSE.md` 明确第三方工具不继承本项目代码许可。

保持现有 Source、Event、Claim、Citation 和 JSONL Schema。保留原件、原始时间精度、字符串大整数消息 ID、回复关系、上下文与不确定性；不要求所有聊天先转为 JSONL。

## 4. 其他工具的处置与研究产物

PyWxDump、wechatDataBackup、WeFlow 5.1.0 与 WechatExporter iOS 备份路线仅登记固定来源与限制，不保存更多大文件。核查历史 fork、补丁和打包分支，但不凭功能列表、名称或 star 数推导来源可信。

形成有直接来源链接的 Markdown 研究报告，保留方法边界、重要分歧、未验证项和停止理由；内部保留 canonical `report-source.md`、claim/source ledger 与证据缺口矩阵。不额外生成用户未要求的其他报告格式。

## 5. 验证与验收

- 两份源码实际 SHA-256 与大小；遍历全部 Git blobs，重算 Git tree，与上游固定提交完全匹配；独立许可副本与归档字节一致。
- 离线只读校验器及回归测试覆盖损坏、内容替换、许可替换、路径越界、特殊成员、链接与容量限制；检查和 CI 都不执行上游工具。
- 原始归档内可读文本的凭据模式检查，人工排除示例和代码表达式误报；明确二进制审计与恶意软件分析不在完成范围。
- 三个更新技能通过结构检查，并用实际请求场景核对路由、范围与来源处理；不只测试固定措辞。
- 全量单元测试、CLI doctor / validate / privacy-scan / check、JSONL 示例和本地 HTML 渲染、两次确定性构建、Markdown 路径与 diff 检查。
- 不把机器检查成功作为聊天真实性、程序安全、隐私授权或当前微信兼容性的证明。

## 6. Git 交付

从当前已合并的 main 建立独立 `codex/chat-tool-archives` 分支/worktree，保护原 checkout 和无关修改。完成阶段只提交本任务文件，保留 request、plan、completion 变更记录。验收后检查最新远端，安全集成到 main，推送并读回远端提交和 CI 结果。

不强推、不改写已有历史、不创建 PR/Release/tag、不部署。若存在无法安全分离的并行修改或新的发布阻碍，说明实际状态并请求方向，不覆盖用户工作。

## 非目标

不新增公开 CLI/API/平台 Schema，不开发或打包自己的微信导出器，不接入真实账号，不提取密钥，不绕过认证或系统防护，不导入真实聊天，不自动公开聊天原件，也不把软件存档计入校园正式记录或知识索引。
